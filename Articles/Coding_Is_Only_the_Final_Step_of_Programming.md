# Leslie Lamport: Programming ≠ Coding

> **Source:** [Stanford Mathematics — Leslie Lamport lecture](https://mathematics.stanford.edu/events/leslie-lamport-programming-coding)
> **Tags:** `software-engineering` `formal-methods` `thinking`

## Key Insights
- **Programming ≠ Coding**: Coding is only the final step; programming starts with deciding *what* we want to achieve and *how*.
- **Simple mathematics is the best tool**: the most effective way to work through the steps before coding is to use simple math — yet few programmers know how to do this or where to learn it.
- **Real-world applications**: the lecture shows, with examples, how these methods are applied in actual software.

## Original Abstract
> Coding is the last step in writing a program. The first step is deciding what we want to achieve and how. The best methods for working through subsequent steps consist in using simple mathematics. Few programmers know how to do this or where to learn it. This lecture will use various examples to show how this is done, and how these methods are implemented in real software.

## About the Speaker
When you use a computer, you use algorithms developed by Leslie Lamport. Winner of the 2013 Turing Award (often called the "Nobel Prize of computer science"), he is renowned for solving practical problems in the computer industry by building mathematical frameworks for distributed systems and concurrent programming. He is also the author of LaTeX, the document preparation system built on TeX that has become the standard for publishing in the mathematical sciences.

## My Takeaways
- Think before you code: write down the goal and the approach first (even informally), then implement.
- Writing a precise *specification* exposes design mistakes when they are still cheap to fix.
